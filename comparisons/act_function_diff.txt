Line-by-line behavioral differences
- Input construction:
  - C++ builds an inputs vector = [left, center, right, occupancy(local_population), internal resources].
  - Rust signature accepts left/center/right/local_population but the current `act()` ignores them and does not call the NN.

- Neural network usage:
  - C++ calls `nn.forward(inputs)` and interprets returned `(direction, magnitude)` to decide action.
  - Rust `act()` does not call `nn.forward()` at all (NN unused).

- Decision threshold & semantics:
  - C++ uses `magnitude < 0.5` as threshold: gather when small, move when large.
  - Rust always gathers (adds `center` to `resources`) and never moves.

- Resource accounting and costs:
  - C++ on gather: `gathered = center_resources / max(1, local_population)` (splits local resource among occupants) and `resources += gathered`.
  - Rust adds the full `center` to `resources` (does not divide by local population) — overcounts gathering.
  - C++ on move: spends `min(resources, magnitude * movement_cost_factor)` and subtracts from `resources`; Rust never spends.

- Age and side-effects ordering:
  - C++ `act()` does not increment `age` in this snippet (age updated elsewhere in Simulation), while Rust increments `age` inside `act()`.

- Constants & defaults (impacting numeric behavior):
  - C++ static defaults at top of file: `maintenance_cost_per_node = 0.01`, `movement_cost_factor = 0.1`, etc.
  - Rust defines different constants in `Individual` impl (e.g., `MOVEMENT_COST_FACTOR = 2.0`, `MAINTENANCE_COST_PER_NODE = 0.0015`) — these diverge if used.

Why the simulations require `q` + Enter to stop
- The interactive stop is implemented by reading a line from standard input (line-buffered). Terminals buffer input until a newline, so typing `q` alone does not send data to the program until you press Enter. That is why you must type `q` then Enter.

How to make stopping accept a single keypress (options)
- Quick change (Windows/Unix): switch from line-based `read_line` to a single-character read in raw mode. In Rust you can use the `crossterm` or `termion` crates to read single keys without Enter.
- Portable & minimal: spawn a small thread that uses `getchar()`/`_getch()` via a small conditional compilation wrapper (Windows vs Unix) to read a single byte. This avoids changing the rest of the input handling.
- Safer: use `crossterm::event::read()` and check for `Event::Key(KeyCode::Char('q'))` in a non-blocking/polling mode.
